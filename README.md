# Q&A With Ethan & Brianna

Live at https://qa-with-ethan-and-brianna.vercel.app

Conversation-starter questions for couples. Pick a vibe and get 20 fresh questions for date nights, walks and long drives. They're generated by Google Gemini, and questions you've already seen aren't repeated.

- **Eight vibes:** Surprise Me, Playful, Big Ideas, Just Us, Deep Talk, Would You Rather, Quick Fire and Spicy (18+, locked until both players confirm)
- **One ask per card:** every question asks for exactly one answer, enforced in the prompt, on the server and in tests
- **Play mode:** one card at a time, with swipe or arrow-key navigation and a "who answers first" turn indicator
- **List mode:** see the whole deck at once and mark questions as answered
- **Saved questions:** heart a question to keep it, then replay your saved ones as a deck
- **Taste feedback:** hearts and "Not for us" thumbs-downs steer future AI decks
- **Play on two phones:** start a room, share the 6-letter code or link, and both phones follow the same card
- **Memories:** jot down each other's answers on any card; the Memories page keeps them as a timeline (on-device only)
- **Share as image:** any question can be shared as a 4:5 card image, or as plain text
- **Stays awake:** the screen won't dim while a deck is open (Screen Wake Lock, where supported)
- **Card motion:** decks deal onto the table, cards flip in, tilt as you drag and fly off when swiped (all disabled with reduced motion)
- **Friendly rate limiting:** if the firewall limit is hit, the app deals saved questions and shows a live countdown until fresh ones are available
- **Works offline:** installable PWA with a built-in starter deck plus a cache of previously generated questions
- **Private by default:** names, saved questions and history stay in the browser's local storage

## Architecture

```
index.html, index.tsx, App.tsx   React 19 SPA (Vite 8, Tailwind 4)
components/, hooks/, lib/        UI and browser helpers
services/questionService.ts      calls /api/generate, caches results, offline fallback
data/starterDeck.ts              hand-written questions used offline
shared/vibes.ts                  vibe definitions shared by client and server
data/spicyDeck.ts                hand-written 18+ cards (lazy-loaded, never sent to the AI)
shared/singleAsk.ts              the one-ask-per-question checker
api/generate.ts                  Vercel function: question generation (the only place the API key lives)
api/room.ts                      Vercel function: two-phone rooms
server/                          prompt builder, validation, quota and bank, Redis store, Gemini client
scripts/eval-questions.ts        question quality report (npm run eval)
tests/                           Vitest tests for the API layer
```

The browser never sees the Gemini API key. `/api/generate` builds the prompt server-side, calls Gemini with a JSON response schema, then validates and de-duplicates the output before returning it.

### Models

The server tries the models in order. If the primary model is rate limited, overloaded, times out or no longer exists, it falls back to the next one.

| Env var | Default |
| --- | --- |
| `GEMINI_MODEL` | `gemini-3.8-flash` |
| `GEMINI_FALLBACK_MODEL` | `gemini-3.1-flash-lite` (set to empty to disable) |
| `GEMINI_THINKING_LEVEL` | unset (model default). `minimal`/`low` make responses faster |
| `DAILY_AI_LIMIT` | `18` AI calls per Pacific day across all users |
| `PER_IP_DAILY_AI_LIMIT` | `5` AI calls per Pacific day per IP address |

When Google ships a new model, you can switch to it by changing `GEMINI_MODEL` in Vercel. No code change is needed. Setting it to `gemini-flash-latest` tracks the newest Flash model automatically, at the cost of the model changing without notice.

### Quota, question bank and rate limits

The Gemini free tier allows 20 requests per day **for the whole project** (it resets at midnight Pacific), so one busy visitor or bot could otherwise use it all up in minutes. Protection is layered:

1. **Vercel Firewall rule** on `/api/generate`: at most 3 requests per 10 minutes per IP, blocked at the edge before the function runs.
2. **Daily AI budget** in Redis: `DAILY_AI_LIMIT` calls per Pacific day in total and `PER_IP_DAILY_AI_LIMIT` per IP.
3. **Question bank:** each AI call asks for 30 questions, serves 20 and banks the rest per vibe. Once the budget is spent, decks come from the bank (questions that person hasn't seen yet), then from the built-in deck.

The browser can't read the firewall's window, so it estimates the countdown from its own recent requests (`FIREWALL_WINDOW_MS` in `services/questionService.ts`; keep it in sync with the rule). While the countdown runs, the app does not call the API.

Redis is the Upstash database behind `KV_REST_API_URL` / `KV_REST_API_TOKEN`. Without it, the app still works, but limits are per server instance only.

### Spicy (18+)

Google's [Generative AI Prohibited Use Policy](https://policies.google.com/terms/generative-ai/use-policy) forbids sexually explicit output, so Spicy is split: Gemini generates flirty and suggestive cards, and the explicit cards come from `data/spicyDeck.ts`. Explicit cards are marked `local` and are never sent to the API, whether as history or as feedback.

## Moving from the old address

The app used to live at `q-a-together.vercel.app`, and that address still works. Saved data is stored per address, so the old address shows a **Move my saved questions** banner. It packs this device's saved questions, memories and settings into a link fragment (which is never sent to a server) and opens the new address, where the user confirms the import. The 18+ confirmation is not carried over.

## Question quality

```bash
npm run eval                 # lint the bundled decks and prompt examples (free)
npm run eval -- --vibe deep  # also generate and grade one AI batch (uses 1 of the 20 daily requests)
```

## Run locally

Prerequisites: Node.js 20.19+ (22 recommended).

```bash
npm install
cp .env.example .env.local   # then paste your GEMINI_API_KEY
npm run dev                  # http://localhost:3000, and /api/generate works too
```

Without a key the app still runs and deals questions from the built-in deck.

```bash
npm run check     # typecheck + tests + production build
npm run preview   # serve dist/ with the production security headers
```

## Deploy (Vercel)

1. Import the repo in Vercel. The framework is auto-detected from `vercel.json`.
2. Add `GEMINI_API_KEY` under **Project Settings → Environment Variables** for Production (and Preview if you want it).
3. Deploy.

### Rotating the API key

1. Create a new key in Google AI Studio.
2. Replace `GEMINI_API_KEY` in Vercel and redeploy.
3. Delete the old key in AI Studio.

## Security

- The API key is server-only. Nothing is passed through Vite's `define` and there are no `VITE_` variables.
- `/api/generate` accepts only same-origin `POST` requests with a JSON body. It checks the request size and the input shape, and caps the history it forwards to Gemini.
- User-supplied history is stripped of control characters and put in a delimited block. The model is told to treat it as data only.
- Model output is schema-constrained, then validated again: length limits, de-duplication and category whitelisting.
- Error details stay in the server logs. Clients only get stable error codes.
- Each warm function instance applies a best-effort, per-IP rate limit (8 requests per 10 minutes). For a hard limit, add a Vercel Firewall rate-limit rule on `/api/generate`.
- Security headers (CSP, frame blocking, nosniff, referrer and permissions policies, HSTS) are set in `vercel.json` and mirrored by `npm run preview`.
- Fonts are self-hosted, so there are no third-party requests at runtime.
